# LifeHub 本地模块：普通用户操作与工程交付指南（目标流程）

**状态：面向下一轮本地化模块的产品/验收指导；不宣称现有 M1 Draft 已提供一键图形安装。**
**依据：** [LH-D-LOCAL-002](https://github.com/Dmnzgh212/AcademicOS/blob/docs/lifehub-supreme-direction-reaffirmed/docs/lifehub/LOCALIZATION_AND_USER_ACCEPTANCE_DIRECTIVE.md)；[M1 技术门槛修订](https://github.com/Dmnzgh212/AcademicOS/blob/docs/lifehub-m1-acceptance-gate/docs/lifehub/M1_ACCEPTANCE.md)。

## 1. 用户只需要做什么

用户不需要编写 Wasm/WAT/Python、读开发者接口规范、制作 provider/consumer 或检查开源依赖安全性。

**用户最小操作：**
1. 从可信的 LifeHub 模块目录/本地文件**导入**由工程人员准备好的安装包；
2. 查看模块能做什么、需要读取什么资料/是否联网、开发/来源信息，并决定**允许或拒绝授权**；
3. **运行**模块并看得懂它的结果、状态和最近一次操作；
4. 能**停止、撤销权限、禁用或卸载**模块；明白停止后台任务与卸载不是同一回事；
5. 出问题时，**复制错误提示或导出脱敏诊断报告**发给工程人员/AI 助手处理；
6. 可以做直观的安全判断（如课程助手为何索取完整磁盘/支付权限），但不承担专业安全审计责任。

这个列表是**交付体验目标**。如果当前工程原型只能通过多行 CLI、手动 digest 和 Python 环境才能安装，必须在交付记录写为**易用性缺口**，不能强迫普通用户先成为程序员；工程团队应提供安全的安装/诊断封装。

## 2. 工程团队和 AI 助手负责什么

项目工程人员或 AI 工程助手接收功能需求、寻找开源先例，在许可允许的范围内选择性复制所需代码，完成本地裁剪与 LifeHub 接口适配。复杂 Wasm/数据库/加密等基础设施优先保留成熟可信依赖而非自行重写。

交付前负责：
- 来源、版本、许可证和版权/NOTICE，审查移植/修改后的代码与依赖；
- 统一输入输出和最小权限、可撤销授权、身份和运行快照绑定；
- 检查隐私和外发行为；不得将原项目 API key、遥测或默认同步暗中保留；
- 在可复现环境中构建已审核的安装包，测试篡改、超大输入、安装、运行、出错、撤权、停用、卸载及恢复；
- 使用目标 OS 的真实安装产物跑自动回归；确认不会无限自动重启、残留敏感日志、越权访问；
- 在有重大未封闭风险时拒绝交付或明确限制功能，**而不是将危险“先给用户试试”**；
- 提供简单安装入口、一页说明与错误报告方式；必要时由工程人员远程指导，但用户无需提供密钥或完整私有数据库。

**本地化 ≠ 自动安全。** 复制的代码同样可能有漏洞、许可证义务和长期更新成本。只复制必要部分，并记录上游变更以便修补。

## 3. 最小示范用例与验收

选一个真实有用的模块（例如课程公告整理、个人日历导入或公开 RSS 摘要；选择开源合法来源，不接触真实凭据作为首轮演示）：

| 角色 | 验证要求 |
| --- | --- |
| 工程/AI 接入者 | 显示来源和本地修改、经批准的包、无 Core 特例修改、运行/撤权/卸载/恢复和安全证据 |
| 普通用户（适当阶段） | 能导入、启动、看到结果、拒绝或撤销不合理权限、复制脱敏报错 |
| 项目审查者 | 评估代码/CI/安全边界和仍缺失风险，决定是否允许技术 Alpha；不需要外部人类贡献插件源码 |

**M1 当前先检查 Engine 的既定技术/安全场景**，用户体验试运行是后续本地模块交付环节，不作为找外部人类程序员的隐形前提。

## 4. 错误报告约定

用户可以只发送：
- 系统版本、LifeHub 版本（如易于复制）；
- 执行了什么操作、预期看到什么、实际看到什么；
- 错误编号/消息，或产品生成的**脱敏**诊断文件。

工程工具生成诊断包时必须默认排除：authkey/token/password、私有邮件/课程个人信息正文、完整数据库、用户主目录文件、所有访问凭据。无法保证脱敏前需显式告警并征求用户确认，不能为了调试而默认上传全部数据。

## 5. 明确不要求的工作

- 让产品所有者找一个会写 Wasm 的朋友以满足 M1。
- 用户从 GitHub 下载陌生代码，未经审查直接运行并授予广泛权限。
- 用户会做渗透测试、验证密码算法、处理许可证冲突或自己修复源码漏洞。
- 用未经验证的“一键安装/零风险”宣传掩盖当前 CLI 复杂性和已知 Engine 资源限制。

**定位：** 开放源代码供工程吸收和改造，**在本地被平台统一管理和最小授权**；尽可能降低普通用户的操作成本，同时不降低工程团队的安全责任。
