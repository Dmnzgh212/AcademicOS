# 01 · 工作区结构基准与分步重建

状态：**仅完成结构文档；现有网站仍未复现并通过 PPT 验收。**

本次提交只改文档。设计来源是用户认可的 `LifeHub_platform_design_v2.pptx` 第 2 页「课程与项目中的工作区」。第 1、4、5、6、7 页分别另做模块；第 3、8 页的执行链路另行验证，不在这一阶段展开。

## 1. 先固定页面结构

只取 PPT 中的应用窗口内容区，排除幻灯片标题、下方说明和外围留白。原生窗口控制由宿主提供。

| 区域 | 第 2 页的目标结构 | 此阶段的边界 |
| --- | --- | --- |
| 左侧 | LifeHub 品牌；当前学期/项目树；当前项目高亮；底部连接入口 | 全局安排/lib 等入口后续接回，不用这些页面的工具栏占据当前工作区 |
| 顶部 | 学期 → 项目 → 当前工作；右侧连接状态 | 搜索与备份不能挤占项目与工作路径 |
| 工作区页签 | Source / Report / Run history；右侧 Export report 和次要菜单 | Browser 属于第 5 页的工作模式，不默认混进第 2 页的页签 |
| 中央左 | 一个原材料文件页签；文件工具栏；连续阅读区 | 保留 PDF/正文和版本能力，工具不堆成第二套大表单 |
| 中央右 | 一个结果文件页签；Preview / Raw；报告内容 | 与原材料同时可见，不把产物改成全宽首页 |
| 最右侧 | This run；步骤时间线；当前步骤说明与动作；底部文件保留状态 | 默认只有本次运行；项目资源页签属于第 7 页，在那一阶段接回 |
| 底部 | 简洁的窗口状态 | 第 2 页没有第 5 页的 Recent actions 区块，不从阅读区域另切出一条大栏 |

中央原材料和结果是两块相邻的独立阅读面板；右侧运行栏是一块独立面板。三块面板从相同的顶部起点开始，共用内容区底部，不出现嵌套的另一套右栏。

比例先从 PPT 窗口截图估计：左侧树约占整体宽度 14%，右侧运行栏约占 20%，剩余给并排阅读；原材料/报告约 44:56。这只是布局起点，不是已经量测或通过视觉验证的像素规范。先使用 1600×900 的应用视口对照，再核对常见桌面尺寸。配色以白灰和清晰的正文为主，绿色用于选中状态、执行状态与主要动作。

## 2. 当前已知差异

依据现有源码检查，不把它冒充实际浏览器截图结果：

| 已知差异 | 代码证据 | 下一阶段怎样处理 |
| --- | --- | --- |
| 工作区固定四个页签，混入 Browser | [workbench.js](../ui/workbench.js) 的 `tabs` | 按第 2 页模式只保留三个页签；浏览器模式另做 |
| 文档下方多出 Recent actions | 同文件的 `render` | 从第 2 页移出，保留给第 5 页 |
| 默认运行栏有「本次运行/项目资源」两页签 | 同文件的 `render` | 第 2 页先复现单一运行栏；资源切换在第 7 页实现 |
| 左侧和顶部混合了多个全局页面的入口 | [shell.js](../ui/shell.js)、[workspace.css](../ui/workspace.css) | 先固定项目工作区模式，不把全局导航和项目内导航混为一层 |
| 原材料/报告、工具栏和阅读区的比例尚未核对 | CSS 为固定侧栏宽度和多处媒体查询 | 先验证骨架比例，再放入实际内容，不能靠更多组件掩盖比例差异 |

正文大小、颜色、滚动、PDF 工具栏等还需真实浏览器对照。函数/DOM 模拟测试通过，只能说明逻辑检查通过，不能把状态改成「已复现 PPT」。

## 3. 小步提交顺序

| 提交 | 唯一目标 | 交付后留下什么 |
| --- | --- | --- |
| 01 · 已提交 | 锁定第 2 页结构及源码已知差异 | 本文；修正未验收状态 |
| 02 · 骨架已提交，视觉待核对 | 只实现左树、顶栏、页签、三块面板的静态骨架 | 一个可独立查看的骨架；记录尺寸和仍存在的差异 |
| 03 | 只接原材料阅读面板 | 文件页签/工具栏/正文或 PDF；记录实际阅读表现 |
| 04 | 只接结果面板 | Preview/Raw/导出；原材料仍同时保留 |
| 05 | 只接本次运行栏 | 真实步骤、等待和文件保留状态；不伪造完成状态 |
| 06 | 组合已经核对的工作区模块 | 组装第 2 页，再安排下一页面 |

本轮停在 **02**（见 [02 阶段记录](02-workspace-skeleton.md)），不会连带完成 03–06，更不会同时重做安排、lib、监控、Skill、来源适配器或 Windows 后台执行。

每个提交做到可保存、可复查、可恢复，再结束该阶段。只运行与本次变更相称的检查；有差异就修当前模块，不自动扩大范围。源文件、差异和状态留在 GitHub，最终在网站组装阶段接入稳定模块。当前线上页面只是已有预览，不作为新结构的正确基准。
