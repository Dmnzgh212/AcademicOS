# LifeHub · 8 页设计的配套实现计划

日期：2026-10-15。性质：全局实施基准；P0 提交仅为文档，后续实现分别记录阶段范围与验证，不据此自动更新网站或运行时。

核对修订：见 [设计与计划核对记录](DESIGN_PLAN_AUDIT_2026-10-15.md)。本计划已补充浏览器操作前置监控、工作创建/运行持久化、PDF/报告产物和跨页面入口；这些是待交付项，不是已完成能力。

**产品目标：让一个人在课程与工程项目之间，持续采集和整理资料、阅读与处理材料、保存成果，并能看见和接管执行过程。** 日程是其中一个入口。界面以用户已认可的 PPT 为准；工程按小模块提交，最后由已核对的模块组成网站。

## 2. 8 页分别落在哪里

| PPT | 结构与操作 | 实现模块与数据 | 验收证据 |
| --- | --- | --- | --- |
| 1 · 全局安排 | 全局导航；学期/课程/项目树；Week/Agenda 与范围选择；时间轴；继续工作表；Upcoming/Source updates 右栏 | `shell` 全局模式、`schedule`；Event、Work、SourceCheck 投影 | 同一组事件在周视图/列表一致；来源/个人事项可辨；范围同时作用于各栏；时间、冲突与跨日处理真实 |

模式规则：全局安排/lib 使用全局导航；阅读工作区使用第 2 页三页签；浏览器工作模式使用第 5 页导航。第 7 页的资源切换只扩展对应右栏。共享导航组件通过模式配置复用，不把所有入口叠进每一页。

入口必须闭合：Continue 和课程/项目下的工作列表打开同一 `workId`；Updates 打开来源变化清单并能返回对应材料/工作；Library、Workflows/资源目录、Connections 分别连接现有模块或小型设置面板。第 2 页不为此增加全套全局页签。先提供最小的“创建工作”入口：所属课程/项目、材料引用、处理要求和期望产物；缺材料可保存为待补充，不自动启动。课程/项目首次可沿用已有配置，不能用写死的示例树通过数据验收。全局搜索先支持名称/元数据定位；正文检索单独按实际需要扩展。

## 3. 布局复现的方法

先以 1600×900 应用视口核对，再检查 1440×900 与 1280×800；更窄尺寸允许明确的横向滚动/收起次要栏，不能悄悄改成另一种产品。第 2 页左树约 14%、运行栏约 20%、余下双阅读区约 44:56，是待截图校正的初始估计。

固定设计变量：背景/边线/正文层级、绿色选中状态、字号、间距、栏宽、工具栏高度、面板滚动边界。先沿用现有 CSS 和本地图标；对照 PPT 修正，避免另起一套视觉语言。状态不能只靠颜色区分。保留清晰的键盘焦点和可读正文。

每个界面提交附同尺寸 PPT 窗口裁图、实际页面截图、差异表；逐项核对布局、信息层级、文字、交互与溢出。真实浏览器对照尚未完成，静态 HTML 和 Node 检查不构成视觉通过。若当前环境仍无支持的浏览器能力，提交写明“待视觉核对”，停在该布局检查点，不通过继续堆面板掩盖问题；接口研究可独立继续。

## 4. 架构决定：一份本地事实，多种界面

首个可用形态是 Windows 本地工作站：同一套静态 UI 由本地宿主提供，工程提供简单启动入口。现有托管 Site 保留为预览与已有浏览器演示；不要求远程网页直接读取 SQLite、任意 Windows 路径或启动任意脚本。浏览器内缓存不能充当后台任务的唯一事实来源。

| 层 | 职责 | 边界与复用 |
| --- | --- | --- |
| Shell | 布局、阅读位置、筛选、等待与接管反馈 | 纯展示组件 + 适配器；不授予权限、不解释数据库表来执行动作 |
| Workstation application adapter | 页面查询、命令校验、版本投影、运行与文件引用 | 新增业务层，复用已有来源/文件/工作逻辑；不新增通用 Core 能力 |
| 本地受控 transport | 将查询/命令送到 application adapter | 复用仓库 loopback/Host/Origin/token 模式；新文件读取同样鉴权；不直接扩宽旧 handler；不上远程监听 |
| 来源与工作执行 | 采集、有限脚本、聊天桥接、暂停与恢复 | 优先复用 Python 采集和现有扩展；具体执行器可替换；有授权和范围校验 |
| 本地持久层 | 来源对象、不可变材料/产物、版本、运行事件、资源快照 | 复用 SQLite 与受控文件目录；浏览器仅保留 UI 状态/可重建缓存 |
| Engine | 既有受管能力边界 | M1 栈单独审阅；产品适配不等于批准该栈、合并 Draft 或完成 M1 |

先以应用适配器验证数据与界面，无须为每个按钮制作 Wasm 包。需要后台受管执行时，再按已经验收的公开契约接入；候选运行时不能当作已发布依赖。UI 与采集可以前进，后台持续运行/恢复的验收必须等真实适配和目标环境验证。

本地 transport 的接入实验先只做“一份指定材料的只读查询”。原有 web 模块不是现成文件服务：需在应用层验证读取授权、文件 ID、长度限制和 MIME，拒绝路径穿越；本地令牌不写入 URL/日志。PDF worker/原件预览按最小需要配置 CSP，不简单放开全部来源。若与冻结 Core 冲突，保持隔离适配实验，不修改 Core 绕过问题。

### 4.1 拟定的应用记录契约

这是工作站业务契约草案，不宣称是当前 Engine ABI。首次代码提交须给出 schema、上限和兼容迁移；命名可局部调整但语义须保持。

| 记录 | 最小字段与不变量 |
| --- | --- |
| Context | `contextId, kind, termId, courseId?, projectId?`；课程是业务分类，不进入通用 Core 类型系统 |
| Source | `sourceId, contextId, adapterId, locator, scope, enabled, lastAttempt, lastSuccess`；凭证不进 Shell 记录 |
| Check | `checkId, sourceId, status, cursorBefore, cursorAfter?, counts, error?, startedAt, endedAt`；partial/failed 不冒充成功 |
| MaterialVersion | `materialId, versionId, previousVersionId?, sourceId?, sourceKey, originalArtifactId, contentHash, capturedAt`；已有版本不可原位覆盖 |
| DerivedText | `versionId, extractorId, extractorVersion, status, textArtifactId?, error?`；读取失败不产生“可学习”假文本 |
| Work | `workId, contextId, title, instruction, expectedOutput, materialRefs, revision, status`；创建/修改要求不等于启动；材料不足可待补充 |
| Run | `runId, workId, workRevision, contextId, inputVersionIds, resourceSnapshot, status, createdAt`；输入、要求和资源在开始时固定 |
| RunEvent | `eventId, runId, seq, stepId, kind, occurredAt, targetId?, artifactIds?, detail`；事件去重、按序显示，不靠 UI 定时假进度 |
| Artifact / Use | `artifactId, kind, relativeLocation, hash, bytes, runId?, inputVersionIds`；界面用 ID 查询，路径仅显示；Use 连接材料版本与工作 |
| BrowserTarget / Frame | `targetId, sourceId, runId, tabBinding, verifiedUrl`；frame 带 `capturedAt, seq, status`，临时存放，不进入资料索引 |
| ResourceVersion | `resourceId, kind, version, hash, entrypoint?, scope`；运行快照保存确切版本，不只存“latest” |
| Event | `eventId, contextId, start, end, timezone, origin, evidenceIds, status`；个人计划、来源事实、待确认候选不混淆 |

文件派生键采用 `原件内容 hash + 解析器版本 + 解析选项`；同字节可复用提取结果，来源/课程引用仍分别保留。相同内容不代表两个来源是同一个来源。

### 4.2 查询、命令和结果

查询：`getWorkspace(contextId, workId?)`、`listMaterials(scope, cursor)`、`getMaterial(versionId)`、`readArtifact(artifactId)`、`getRun(runId, afterSeq)`、`getResourceCatalog(scope)`、`listSchedule(range, scope)`。大列表有分页和字节上限；不可把无限量资料一次塞入网页。

命令：`saveWork(contextId, workDraft, expectedRevision?)`、`checkSource(sourceId)`、`startWork(workId, inputVersionIds, resourceVersions)`、`controlRun(runId, pause|resume|stop)`、`controlTarget(targetId, takeover|return|focus)`、`selectNextResource(projectId, resourceVersion)`、`exportArtifact(artifactId)`。这是逻辑操作名，接入步骤再映射具体 transport；不预造第二套通用 RPC。`scope` 是请求范围，由宿主校验实际授权，不能靠客户端字段自行取得权限。

每条变更命令携带 `commandId + expectedRevision + scope`；结果是 `accepted/rejected`、关联的 `runId/checkId` 和错误码。accepted 只表示受理，完成必须来自持久事件。重试不重复启动；版本冲突返回可理解提示。首次可用版本通过带游标的增量查询刷新运行栏，不为此先加消息总线。

浏览器状态区分：连接/断开；自动/暂停请求中/已暂停/接管请求中/用户控制/交还校验中/停止请求中/已停止/错误。等待 worker 确认后显示完成；“请求停止”不写成“已停止”。失效页面交还失败时保持暂停，不自动在另一页接着输入。

**浏览器操作前置条件：** 真实自动导航、点击、填写或浏览器抓取之前，须通过 M1（监控步骤，与 Engine M1 里程碑无关）和 M2 的最小验证，且当前目标画面/状态可见、停止/接管可用。失去监控时停止发出下一动作，显示断开，不能在冻结画面后静默继续。监控接入本身可以只观察用户选定的静态测试页，不启动自动爬取。此前的 D1/I1 可先处理本地导入或只读源站采集；若选浏览器路径，额外依赖 M2。聊天桥接也遵守此规则，不覆盖草稿。

只读源站接口采集也须显示实际检查/下载状态、当前来源和停止反馈，不伪造浏览器画面。若认证/会话刷新需要启动浏览器，同样遵守上述监控前置条件。

### 4.3 旧数据迁移

当前浏览器 localStorage/IndexedDB 与 Python 数据库没有共同权威。迁移前导出旧状态与原件清单，核对实际文件；用稳定映射表保留旧文档、工作、来源、版本 ID 的对应关系。先 dry-run 显示可导入/缺失/冲突，再导入临时区、校验、切换读路径；保留旧数据和回退入口。一次只指定一个写入方，不做“浏览器和 Python 同时修改同一材料”的双写同步。缺失原件保留元数据并标缺失，不生成替代原件。

## 5. 首个闭环与增量规则

先选一个课程或项目的一份已授权来源，支持“手动检查一次”；完成后才启用定期检查。第一条有效工作定义为：来源有一次可验证变化，保存原件与文本，工作按固定版本读取，输出一份带来源引用的整理报告，保存后可重开。这个闭环使用确定性整理脚本即可完成；模型辅导/复杂分析另接，不能把拼接文本称作完成学术分析。

1. 绑定来源、目标与范围；标清单页抓取、指定课程遍历、附件下载各自支持范围。
2. 建立 check 记录并锁定相同来源任务；先比较可用游标/远端指纹/元数据。无此能力的页面仍需读取后比较，不承诺零网络读取。
3. 只对确认变化的项目下载/读取；失败保留上一有效快照与游标。部分成功按子来源记录，不把部分失败推进成全局成功。
4. 原件先写临时文件、校验后发布；生成不可变材料版本。SQLite 与文件不具全局事务，使用暂存/提交标记和启动清理使中断可辨，不假称原子提交。
5. 命中派生键即复用文本/索引；变化才提取并更新索引。扫描 PDF 的 OCR、Office 解析不在首个闭环默认范围；能力缺失显示等待，不输出空成功。
6. 产生更新记录和可继续的工作入口。已有运行仍固定旧版本，新建运行才选择新版；不强制每次轮询自动启动模型会话。
7. 保存报告和 provenance；从 lib 的 Used by、工作区原材料/报告以及运行记录互相打开。

无变化仍允许写轻量检查时间/健康记录；不能重写所有 `text.md/source.json/index.json` 再宣称“完全跳过”。同大小不代表内容校验通过，文件完整性应有按需 hash 校验。首轮不建向量库，文本索引先比较仓库已有搜索与 SQLite FTS5 的适配成本，确认需要再接。

## 6. 小步交付顺序

编号表示依赖顺序，不是要一次全写完。每行是一项独立交付；表内存在两个可分离动作时拆成两个提交。UI 线在每次结构验收后接一个真实数据点，避免所有页面做好后才发现后台接不上。B 后台线保持隔离，接入点明确。

以下 M0/M1/M2 是监控模块的步骤编号；项目 Engine 的 M1 是另一条验收线，两者不可混称。条件依赖写在表内；最小拓扑顺序允许调整，不能跳过前置验收。

| 步骤 | 依赖 | 一次交付的范围 | 本步通过条件 |
| --- | --- | --- | --- |
| P0 · 本文 | 已有 01/02 | 完整设计映射、接口草案、复用与接续点 | 文档链接/路径/提交范围核对；无 UI 或运行时变更 |
| W0 · 骨架校正 | P0、02 | 只核对和修第 2 页骨架 | 实际截图对照三栏、三页签、路径与留白；仍有结构差异就停在本步 |
| W1 · 原材料 | W0 | 只接实际文本/原生 PDF 阅读器 | 原件可读、缺失/格式不支持有提示、滚动独立；不添加无效 PDF 控件 |

## 7. 技术选择与暂不扩张的范围

- PDF：W1 可先复用原生 viewer 验证实际阅读；这只算功能中间检查点。若其工具栏与 PPT 不一致，记录为未解决视觉差异，不能把原生阅读通过等同 PPT 通过。随后单独做固定版本 PDF.js 等成熟实现的最小适配实验，比较页码/缩放、文字、worker/CSP、体积与错误文件；通过后再替换 reader adapter。D3 明确交付 PDF 正文，不手写解析器。
- 报告：先安全文本/现有 Markdown 能力；表格、公式、图片是独立增量。需要时选择维护中的解析器与净化器，固定版本/许可证，验证不可信 HTML/链接。不借报告面板执行任意 Python 或 JavaScript；分析由受控脚本产出数据/图片/报告。
- 来源：先现有 adapter；Brightspace 代码具备会话复用和接口采集路径，但用户环境的端点权限、登录有效性、页面结构仍需实测。浏览器抓取与源站只读接口按实际可用性择一，不新增模型 API。首个闭环不扩到邮件/所有课程/所有附件。
- 目录更新：受控目录扫描生成 Skill/Method/Script 版本；默认不监听所有磁盘、不自动运行新脚本。先手动检查更新，稳定后再轮询；应用行为与权限变更分开处理。
- 引擎/算法：沿用现有受控接口；习惯蒸馏、PersonIR、新权限语言、向量记忆、通用自动规划、插件市场都不作为这次 PPT 实现的先决条件。需要恢复此前具体算法方案时先找原文，不用自行发明替代品。

## 8. 验收与中断恢复

分开记录五类状态：结构/视觉、交互与领域逻辑、真实数据链、后台与恢复、Windows 用户交付。每类用“未开始/已实现待验证/已验证/有缺口”，附证据位置与确切 commit；不用一个完成百分比掩盖差别。

针对性验证：修改版本逻辑就测无变化/变化/失败/中断；修改监控就验目标隔离和控制确认；修改 UI 就做真实浏览器对照。沿用有价值的现有测试，不为纯文字或低风险样式变化堆模拟测试。测试通过、PR 数量、部署成功均不替代真实验收。

每个代码提交同时更新一个阶段记录：

1. 范围、PPT 页、依赖与 parent commit。
2. 变更文件及可独立打开/运行的入口。
3. 验证方法、结果与证据；未测项明确写出。
4. 已知差异、数据/许可/运行限制。
5. 下一个最小任务、恢复命令/入口与回退 commit。

视觉证据优先用脱敏测试材料；真实材料不进入公开 fixture/截图包。恢复时从最后一个稳定 commit 开始，不重写整个网站；持久数据回退必须经过备份/兼容迁移，不能只回退 UI 后任其读取不兼容数据。
