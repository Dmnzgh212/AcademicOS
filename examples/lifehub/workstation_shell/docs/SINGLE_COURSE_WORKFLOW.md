## 1. 本次选定的用户场景

用户进入一门已有课程，打开一份课程材料，并保存“我要用它做什么”。首次只要求能阅读、保存要求、再次打开并继续。后续分别加入指定来源更新、已有方法执行、成果和进度关联。

示例要求：“按这份材料解释指定概念，并列出需要进一步确认的问题。”这是用于验证流程的示例，不擅自把某门课程的历史教法变成全平台默认设置。

首个阅读切片使用用户已选定的本地 UTF-8 文本，或宿主已经能返回的原件。原生 PDF 阅读单独验证；PDF 正文解析、OCR、真实来源轮询和聊天执行保留在各自步骤，不因一个阅读入口可用就宣布通过。

## 2. 识别：材料、上下文与工作如何关联

| 情况 | 应有行为 | 用户从哪里理解结果 |
| --- | --- | --- |
| 用户从已有课程/项目进入 | 沿用当前上下文；工作与材料引用分别保存 | 左树选中项、顶部路径、原材料文件名 |
| 来源已有明确绑定 | 变化归入该来源绑定的课程/项目，保留来源和版本证据 | Updates 与材料详情，再进入同一工作区 |
| 只凭标题/路径猜到归属 | 仅给出归属候选及依据；不覆盖原绑定 | 现有来源/材料设置中的待处理项 |
| 同一材料被另一个项目使用 | 复用材料引用，不复制整份原件 | Library 的 Used by 与工作材料列表 |
| 来源发布新版本 | 保存新版并显示“有更新”；当前阅读和既有运行保留指定版本 | 文件名旁的版本状态及材料详情 |
| 只扫描到部分页面或读取失败 | 保留此前有效材料；显示本次范围和失败项 | Updates / 来源检查记录 |
| 新材料没有已有工作 | 可保存材料并创建工作草稿；不自动声明已有处理要求 | 课程/项目内的最小工作入口 |

版本选择必须可解释：继续已有工作先打开它保存的材料版本；用户显式选新版后，才修改下一次运行的输入。材料缺失时显示缺失原因和重新选择入口，不静默切换到同名文件或其他课程材料。

## 3. 选择：先用一项已有方法，逐步支持规则匹配

首个处理切片在现有目录中手动绑定一项有实际用途的 Method/Script，记录其输入、输出、支持格式、项目范围和固定版本。方法不支持当前输入时说明原因，不创建空报告。

下一步才增加受限匹配：根据明确处理要求、材料类型与已有配置筛选候选，并显示选择依据。没有候选或多个候选无法区分时保留工作草稿，用户可选择或补充要求。复用现有资源目录，暂不增加通用自动规划器。

- 脚本能够可靠完成的提取、比较、整理优先交给脚本。
- 需要解释或推理时，生成一份包含明确问题、指定材料引用和期望输出的聊天请求。
- 聊天请求先可查看；真正发送另依赖可用监控、停止与接管，以及当前会话和草稿检查。已有聊天草稿必须保留，不静默覆盖。
- 资源目录发现新版时展示变更；当前运行继续使用已固定版本。选择新版影响后续运行。
- 首次执行按一次用户发起的工作处理。已有规则和授权范围内的后续执行不反复要求确认；不确定的意图或新增范围留待处理。
- 学习习惯蒸馏继续暂缓；用户可以为这次工作填写教法要求，无须先建立个人画像。

这是一组产品行为规则，不证明当前浏览器往返或脚本执行已接通，也不引入付费模型 API 必选依赖。

## 4. 执行与成果：状态来自真实动作

| 阶段 | 页面应该表达什么 | 可以留下什么 |
| --- | --- | --- |
| 只打开材料 | 可阅读、当前上下文和确切版本 | 阅读选择；不产生处理完成记录 |
| 保存要求 | 草稿已保存或保存失败；材料不足则待补充 | 已确认持久化的工作修订 |
| 请求受理 | 已排队，尚未执行 | 固定输入/要求/资源版本与 accepted 事件 |
| 执行中/等待 | 当前步骤、真实等待原因和可用动作 | 实际运行事件；不能用定时器生成成功进度 |
| 失败/停止 | 哪一步失败或已确认停止，已保存部分在哪里 | 错误与可恢复检查点，不伪造完成报告 |
| 成果已保存 | 确切成果可打开，来源与使用版本可追溯 | 原件/报告/其他实际产物及引用 |
| 再次打开 | 重开已有成果，能够继续该工作 | 原运行和新运行分开，不改写历史 |

“报告保存成功”必须在宿主确认保存后显示。重开失败时显示实际错误；空文件、缺失文件和正文未提取各自说明。确定性整理报告只能通过工程流程验收；证明辅导有效，还需使用一份真实材料，检验解释、引用与用户指定教法是否符合要求。

## 5. 回写：哪些状态可以改变

- 阅读材料不等于学会，也不把工作或课程自动标记完成。
- 运行成功并保存成果，只更新该运行及关联成果；学习掌握程度仍未知。
- 工作完成由用户确认，或由事先明确的机械验收条件判定。开放性的“学会”“掌握”不能仅凭模型一句话回写完成。
- 教授来源里明确的日期可作为带来源证据的事实保存；工作建议时间与用户个人承诺分别表示。未知日期保持未知。
- 来源日期变化保留前值和新值，提醒相关工作；不悄悄覆盖个人安排。涉及承诺变更时由用户接受。
- 对下一步的建议可保存为待处理候选；仅在明确规则和既有授权范围内安排执行。
- 失败、停止和部分成果保留在项目工作记录中，重开时可以判断从哪里继续。

## 6. 落在现有页面的最小交互

1. **左树/最小入口：** 使用已有课程或项目数据；用户能选择上下文，再选该范围内的材料。第一轮可以在现有区域提供简短选择入口，不增加总控页。
2. **顶部路径：** 上下文与工作一致；只浏览材料、尚未创建工作时如实表示。
3. **Source：** 仅此切片接入阅读。显示确切文件、版本、加载/缺失/不支持状态；切换时清除旧内容，过期的异步结果不能覆盖新选择。
4. **Report / Run history / This run：** 保持既定位置；尚未接入时保留真实空状态。打开材料本身不产生运行。
5. **保存要求：** 在 C0 接入切片复用现有工作草稿能力和对话框，不占用阅读面板；保存后原文件和阅读位置保留。

完整的 Continue、Updates、Library、资源目录和 Connections 导航仍按 N0 分步衔接。最小的上下文/材料入口随 W1 提供，不把基本阅读入口等到所有页面完成才接。

## 7. 分次交付及证据

| 次序 | 单次范围 | 通过条件 |
| --- | --- | --- |
| W0 · 仍待完成 | 真实浏览器核对第 2 页骨架 | 保存同尺寸截图与具体差异；结构差异先修骨架 |
| W1 第一切片 | 上下文/材料入口 + 一份真实 UTF-8 文本阅读 | 用户能进入、打开、切换；确切版本、独立滚动、失败及缺失状态真实 |
| W1 后续切片 | 原生 PDF 原件阅读 | 指定原件可读，实际控件、尺寸和失败表现可核对；不等同正文提取通过 |
| C0 页面接入 | 保存工作要求并重开 | 草稿保存/失败反馈真实；重开保持要求和材料版本，不自动运行 |
| W2/W3/C0 执行接入 | 分别接成果重开、运行事件、一项有用的固定输入处理 | 每次只交付其中一项，最后连成一次可追溯工作 |
| D1/D2 后续 | 一个已绑定来源的变化入库与派生 | 新增/不变/变化/失败有证据；部分观察不删除旧有效记录 |
| 后续资源与安排步骤 | 一项方法选择/版本更新，再接成果关联与进度建议 | 有选择依据、下次生效、事实与建议区分；不扩大冻结 Core |

后几行是已有阶段的行为约束，不把它们并进下一次实现。浏览器自动化依然以前置监控与接管通过为条件；用户材料迁移依然先做 D0m。
